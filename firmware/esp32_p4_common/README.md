# esp32_p4_common: shared low-level code for the ESP32-P4 screens

A PlatformIO library (`library.json`, name `el_camino_p4_common`) with the parts of the round-screen firmware that
sit below the UI: the MIPI DSI panel bring-up and backlight, the boot splash, the sensor UART parser and link, the
bench drive cycle, the cluster I2C bus, the loop watchdog and a few shared constants. The screen layer, the faces and
the menu are in [`../esp32_p4_ui`](../esp32_p4_ui/); the application is [`../esp32_p4_display`](../esp32_p4_display/).
Overview of all the firmware: [`../README.md`](../README.md).

```bash
test/host/run_tests.sh      # sensor UART parser tests on the Mac (see Known issues: needs one include path added)
```

## Who uses it

| User | What it takes |
| --- | --- |
| [`esp32_p4_display`](../esp32_p4_display/) (all three round screens) | everything (`lib_deps = file://../esp32_p4_common`) |
| [`esp32_p4_display_litmus`](../esp32_p4_display_litmus/) (panel bring-up) | `boot_splash` and one of the panel init tables (`build_src_filter`) |
| [`esp32_p4_ui`](../esp32_p4_ui/) | `sensor_link.h` (`gauge_link`, `gauge_console`, `cluster_peer`), `el_camino_speed.h`, `display_setup.h` (brightness), the `g_elc_dpi_panel` handle (`p4_screen`) |
| [`../scripts/pio_pre_build.py`](../scripts/pio_pre_build.py) | imports `scripts/pio_pre_gfx_dsi_io_hook.py` (see *Build* below) |

## Status

- The sensor UART parser is host-tested (`test/host/test_sensor_packet.cpp`), but the test script does not build as
  it stands (*Known issues*).
- Everything else runs only on the P4 boards. The root [`README.md`](../../README.md#status) says the screens run on
  Waveshare P4 boards on the bench; nothing is in the car.
- Panel profiles in `display_setup.cpp`: Waveshare 3.4C (800×800, SH8601), Waveshare 4C (720×720, JD9365), the
  Espressif P4 EV board with a 720×720 JD9165 module or its 7" 1024×600 panel. Which of these were run on hardware is
  not stated in this directory's code or history, apart from the 3.4C and 4C notes in
  [`esp32_p4_display/platformio.ini`](../esp32_p4_display/platformio.ini).

## Hardware it targets

ESP32-P4 boards with a MIPI DSI panel: the Waveshare ESP32-P4-WIFI6-Touch-LCD-3.4C and -4C (the product's round
screens) and the Espressif ESP32-P4 Function EV board. Pins used here (all build flags, defaults in the code):

| What | Pins | Where |
| --- | --- | --- |
| Sensor UART | RX `SENSOR_UART_RX` (5), TX `SENSOR_UART_TX` (4), 115200 8N1 | `sensor_packet.h`, set by the app |
| Cluster I2C (`TwoWire(1)`) | SDA `CLUSTER_I2C_SDA` 47, SCL `CLUSTER_I2C_SCL` 48, 100 kHz, 20 ms timeout | `cluster_i2c.h` |
| Waveshare PMIC (before DSI) | I2C `0x45` on SDA 7 / SCL 8 | `display_setup.cpp` |
| Backlight | `TSPS_BACKLIGHT_PIN` (26), PWM | `display_setup.cpp` |
| Illumination input | `ELC_ILLUMINATION_GPIO` (24), pull-up, low = night | `display_setup.cpp` |
| LCD reset | `TSPS_LCD_RST` (27; none on JD9365) | `display_setup.cpp` |

## Layout

| File | Role |
| --- | --- |
| `include/display_setup.h`, `src/display_setup.cpp` | `create_tsps_display()`: the DSI bus and panel for the profile chosen by build flags (timings, lane rate, init table), the backlight (`tsps_backlight_set_level()`), the illumination input with debounce (`elc_illumination_gpio_poll()`), the user brightness on top (`elc_backlight_set_user()`), night from CAN on a screen with no input (`elc_illumination_set_external()`) |
| `src/waveshare_3inch4_dsi_800_init.{h,cpp}` | SH8601 init table for the 3.4C (copied from Waveshare's example, MIT, per the file header) |
| `src/waveshare_jd9365_720_init.{h,cpp}` | JD9365 init table for the 4C (derived from Waveshare's `esp_lcd_jd9365`, Apache-2.0, per the file header) |
| `include/boot_splash.h`, `src/boot_splash.cpp` | `elc_boot_splash_framebuffer_write()`: copies the boot image into the DSI framebuffer before LVGL starts |
| `include/bootscreen_rgb565_{800,720,1024x600}_gen.h` | The boot image as RGB565, one per panel size. Generated by [`scripts/export_bootscreen_rgb565.py`](../../scripts/export_bootscreen_rgb565.py) from `assets/bootscreen/boot3.png`; do not edit |
| `include/sensor_packet.h`, `src/sensor_packet.cpp` | `SensorPacketParser`: the 36-byte sensor frame (`AA 55`, 33-byte v4 payload, XOR), resync on bad frames, text lines kept apart from binary frames, the `0xA5` keepalive when asked; `derive()` to gauge units (through `elc_sensor_units.h`) |
| `include/sensor_link.h`, `src/sensor_link.cpp` | `SensorLink`: owns the UART, keeps the last good frame, staleness (`SENSOR_PACKET_STALE_MS`, 400 ms), frames per second, the keepalive (center only), the demo drive, and sensor frames from CAN while the UART is silent (`feedBus()`) |
| `include/demo_drive.h`, `src/demo_drive.cpp` | `DemoDrive`: a 60 s drive cycle (idle, three gears, cruise, pass, stop) as sensor frames, for `demo on` |
| `include/cluster_i2c.h`, `src/cluster_i2c.cpp` | Cluster I2C master on the center: register writes, register reads (the camera's TVP5150 sits on this bus), theme broadcast to `0x3C` / `0x3D`. Also the theme / view enums and the `cluster` NVS keys |
| `include/cluster_i2c_slave.h`, `src/cluster_i2c_slave.cpp` | Slave side on the left / right screens: a register callback |
| `include/elc_watchdog.h` | Loop-task watchdog, 8 s by default (`ELC_LOOP_WDT_TIMEOUT_MS`) |
| `include/el_camino_speed.h` | Wheel RPM to mph (`elc_speed_rpm_to_mph()`) |
| `include/el_camino_firmware_config.h` | Older layout constants for the center's tach and clock (from the Pi version's art) |
| `scripts/pio_pre_gfx_dsi_io_hook.py` | Patches the GFX library's `Arduino_ESP32DSIPanel.cpp` in `.pio/libdeps` (see *Build*) |
| `test/host/` | `run_tests.sh`, `test_sensor_packet.cpp`, and a minimal `Arduino.h` stand-in (`HardwareSerial` over a byte queue) |

## Public API (short)

```cpp
Arduino_GFX *panel = create_tsps_display();      // nullptr if the panel did not start
elc_boot_splash_framebuffer_write(panel);

SensorLink link;
link.begin(Serial1, SENSOR_UART_RX, tx_pin);     // tx_pin -1 = receive only (the side screens)
link.setKeepalive(true);                         // the center only
if (link.poll()) { /* new frame: link.last(), link.derived() */ }
link.fresh();                                    // a frame within 400 ms

cluster_i2c_master_begin();                      // center
cluster_i2c_broadcast_center_theme(theme, view);
cluster_i2c_slave_begin(CLUSTER_I2C_ADDR_TSPS, on_reg, nullptr);   // right screen

elc_loop_watchdog_begin();                       // end of setup()
```

## Build

There is nothing to build here on its own: an app pulls it in with `lib_deps = file://../esp32_p4_common` and the
include path `-I${PROJECT_DIR}/../esp32_p4_common/include`. Dependency: GFX Library for Arduino (`^1.6.0` in
`library.json`; the apps pin `1.6.5`).

The apps run [`../scripts/pio_pre_build.py`](../scripts/pio_pre_build.py) before each build. It copies this
directory into `.pio/libdeps/<env>/el_camino_p4_common` (a `file://` copy otherwise goes stale) and calls the three
patches in `scripts/pio_pre_gfx_dsi_io_hook.py` on the GFX library. Each is idempotent and prints a `pre:` line:

| Patch | Why |
| --- | --- |
| `apply_dsi_panel_io_hook` | keeps the DBI panel IO handle in `g_elc_dsi_panel_io`, for SH8601 brightness by DCS `0x51` |
| `apply_dsi_fb_hook` | makes the framebuffer count a build flag (`ELC_DSI_NUM_FBS`, default 1; the display app sets 2) and keeps the DPI panel handle in `g_elc_dpi_panel`, so `p4_screen` can double-buffer |
| `apply_dsi_phy_clk_fix` | uses the PLL reference clock for the DSI PHY on rev ≥ 3 P4 silicon (the 4C), keeps the old source on the ES chips (3.4C) |

If a GFX update moves the patched lines, the script prints `pre: WARN … pattern missing` and skips the patch; the
SH8601 brightness then logs that the panel IO handle is null.

## Configuration (build flags)

| Flag | Default | Meaning |
| --- | --- | --- |
| `TSPS_WAVESHARE_3C4` | off | Waveshare 3.4C: 800×800 SH8601, PMIC, DCS brightness |
| `TSPS_USE_JD9365` | off | Waveshare 4C: 720×720 JD9365, PMIC |
| `TSPS_PANEL_1024X600` | off | EV board 7" 1024×600 |
| (none of the above) | | EV board with a 720×720 JD9165 module |
| `TSPS_DSI_DPI_HZ` | 80 MHz (3.4C) | DPI clock; the display app sets 48 MHz on the 3.4C to leave PSRAM bandwidth for drawing |
| `TSPS_LCD_RST` | 27 (not JD9365) | panel reset GPIO |
| `TSPS_WAVESHARE_PMIC_I2C_ADDR` / `_SDA` / `_SCL` | `0x45` / 7 / 8 | Waveshare PMIC |
| `TSPS_BACKLIGHT_PIN` | 26 | backlight GPIO; `-1` = PMIC (and DCS on the 3.4C) only |
| `TSPS_BACKLIGHT_USE_PWM` / `TSPS_BACKLIGHT_ACTIVE_LOW` | 1 / 0 | backlight drive |
| `TSPS_BACKLIGHT_LEVEL` | 51 | boot brightness, 0–255 |
| `ELC_ILLUMINATION_GPIO` | 24 | dash-lights input, `-1` = none (then `elc_illumination_set_external()` applies) |
| `ELC_ILLUMINATION_DIM_LEVEL` / `_FULL_LEVEL` | 100 / 255 | night and day backlight |
| `ELC_ILLUMINATION_LOW_IS_DIM` | 1 | set 0 if the harness inverts it |
| `ELC_ILLUMINATION_DEBOUNCE_MS` | 150 | |
| `ELC_DSI_NUM_FBS` | 1 | framebuffers (needs the pre-build patch) |
| `CLUSTER_I2C_SDA` / `CLUSTER_I2C_SCL` | 47 / 48 | cluster bus |
| `SENSOR_PACKET_STALE_MS` | 400 | no frame for this long = no data |
| `SENSOR_LINK_KEEPALIVE` / `SENSOR_LINK_KEEPALIVE_MS` | 0 / 350 | default keepalive (the display app sets it at run time) and its period |
| `ELC_LOOP_WDT_TIMEOUT_MS` | 8000 | loop watchdog |

`display_setup.cpp` stops the build with `#error` if the backlight pin and the illumination pin are the same, or the
illumination pin is the LCD reset.

NVS: `cluster_i2c.h` defines the namespace `cluster` with the keys `th` (theme), `cv` (center view), `tv`
(right-screen variant) and `odo`. Only `th` is used now (by the side screens, `side_main.cpp`).

## How it talks to the rest of the system

- **Sensor UART:** [`docs/protocols/sensor_uart.md`](../../docs/protocols/sensor_uart.md). Every screen receives the
  same 115200 8N1 stream; only the center sends the `0xA5` keepalive (three TX pins on one RX would fight).
- **Cluster I2C:** [`docs/protocols/cluster_i2c.md`](../../docs/protocols/cluster_i2c.md). Master: center. Slaves:
  speedo `0x3C`, right screen `0x3D`. Registers `0x01` theme (0 Classic, 1 Fallout, 2 Modern), `0x02` center view
  (0 Tach, 1 Clock, 2 Media, 3 Efficiency), `0x03` right-screen variant. On the DigiDash board the theme also travels
  on CAN (`0x210`); the side screens take whichever arrives.
- **CAN:** none here directly; `SensorLink::feedBus()` takes the decoded `0x100`–`0x104` frames
  ([`can_bus.md`](../../docs/protocols/can_bus.md)) from the app.

## Extending it

- **A new panel:** add a profile block to `display_setup.cpp` (resolution, DSI timings, lane rate, init table, reset
  and backlight), a flag to pick it, a boot image size in `boot_splash.cpp` (run
  `scripts/export_bootscreen_rgb565.py`), an env in [`esp32_p4_display/platformio.ini`](../esp32_p4_display/platformio.ini),
  and try it first with [`esp32_p4_display_litmus`](../esp32_p4_display_litmus/).
- **A new sensor field:** change `sensor_uart.md` first, then `SensorPacketValues` and `parse_payload()` here, the
  CAN codec in `elc_can`, and add a case to `test/host/test_sensor_packet.cpp`.

## Known issues

- `test/host/run_tests.sh` fails to compile: `src/sensor_packet.cpp` includes `<elc_sensor_units.h>` from
  `../elc_can/include`, which the script does not put on the include path. Adding
  `-I "$common/../elc_can/include"` to the `c++` line makes all the tests pass.
- `library.json` lists only the GFX library, but `sensor_link.h` includes `elc_can_codec.h` and `sensor_packet.cpp`
  includes `elc_sensor_units.h`: the library needs [`elc_can`](../elc_can/) beside it. The apps add its include path
  themselves.
- `display_setup.h` still names the old env names (`esp32-p4-tsps`, `esp32-p4-tsps-ev7`, `esp32-p4-tsps-waveshare4c`);
  the envs are now `display-*` in `esp32_p4_display/platformio.ini`.
- `docs/protocols/cluster_i2c.md` lists only themes 0–1 and views 0–2 and leaves out register `0x03`;
  `cluster_i2c.h` has Modern (2), Efficiency (3) and `0x03`.
